## 3. 已完成的功能與不可破壞規則

### 商品與規格

- 商品類別包含玩具、公仔、戰鬥陀螺；目前商品資料由 Supabase 管理。
- 每個商品可有多個規格／款式；每個規格有獨立 SKU、價格、庫存、安全庫存、預購設定、限購數量與賣貨便連結。
- 現貨顯示實際可售庫存；預購需顯示到貨說明。最新文字應表達「海外出貨、海運、集運、海關與天候會影響實際到貨時間」，不可保證固定 7–10 個工作天。
- 商品圖片由後台上傳；主圖支援 JPG、PNG、WebP，單張上限 5MB。不要在沒有素材時用假商品圖或泛用 stock photo 取代。
- 首頁最新商品格要求：手機 2 欄、平板 4 欄、桌機 4 欄。

### 會員與 LINE

- LINE Login 是會員登入入口。
- 首次登入需補填姓名與手機；生日、收件地址可選填。
- 結帳前必須完成 LINE 官方帳號好友／可推播檢查；未完成可瀏覽，但不可建立訂單。
- 會員可查看自己的訂單、點數紀錄與優惠券。
- 未登入訪客可以瀏覽、搜尋與先加入購物車；目前購物車主要以 `sessionStorage` 保留，尚未視為完整的跨裝置／跨登入購物車同步。若要改善，先提出方案，不要默默改資料模型。

### 購物車與結帳

- 購物車可調整數量、移除品項、查看商品總額。
- 取貨方式：
  - 到店取貨
  - 賣貨便
  - 宅配
- 賣貨便不在本站加運費；7-11 取貨時由超商向客戶收取。
- 賣貨便結帳按鈕文字為「前往賣貨便結帳」。目前會先建立本站「賣貨便待確認」訂單，接著導向賣貨便；管理員再與外部賣貨便訂單核對，確認後才完成本站流程並扣庫存。
- 賣貨便目前只適用現貨，購物車內若有預購需改用本站結帳。
- 宅配在顧客結帳時不計入運費；商品到貨後由客服通知實際運費，顧客將尾款與運費匯款後，管理員確認才寄出。
- 選擇宅配後才顯示且必填：收件人姓名、收件人電話、收件地址。未選宅配時不要顯示這三個欄位。
- 到店取貨可選等全部到貨後一次取貨，或現貨／預購分批取貨。
- 結帳的預估總額只包含商品金額減優惠券／點數折抵；不要把賣貨便或尚未確定的宅配費用加進去。
- 付款方式：匯款／轉帳；符合條件的現貨到店訂單可到店支付。不要新增信用卡、TWQR、全支付或其他線上金流。
- 匯款帳戶可由後台維護多個帳戶；顧客需選擇帳戶並回報匯款帳號末五碼。

### 訂金、庫存與訂單狀態

- 預購商品訂金固定為商品總價 50%。現貨可依規格設定全額或部分訂金。
- 建立訂單後先保留庫存；管理員確認訂金／付款後才正式扣庫存。
- 匯款／訂金未在期限內完成，系統自動取消訂單並釋放保留名額；目前付款期限為 24 小時。
- 管理員更新訂單後需要有明確成功／錯誤回饋、重新載入最新資料，避免重複操作。
- 目前主要狀態：
  - `pending_payment` 待付款
  - `pending_review` 待確認款項
  - `confirmed` 已確認
  - `partially_ready` 部分可取貨／部分到貨
  - `ready_for_pickup` 可取貨
  - `completed` 已完成
  - `cancelled` 已取消
  - `refund_pending` 退款處理中
  - `refunded` 已退款
- 後台營運概況需保留「賣貨便待確認」統計、待確認款項、可取貨、低庫存與會員數等重點數字。
- 每個規格可設定安全庫存；可售量達 3 件或以下時通知管理員。
- 庫存異動、訂單狀態歷程、付款確認與管理員操作必須保留不可覆寫紀錄。

### 點數與優惠券

- 預設每消費 NT$100 累積 1 點，1 點折 NT$1；後台可修改累積門檻、點值、最低使用點數與單筆折抵上限。
- 點數目前永不到期；管理員完成訂單核銷時入帳，退款／取消依規則扣回。
- 優惠券為固定金額折扣；後台可設定是否與點數併用、限定商品／會員、有效期限與使用次數。
- 生日券規則由後台設定；目前以保存會員生日與自動發送為主。
- UI 必須清楚區分「可用點數」「本次折抵」「訂單完成後才入帳」等狀態，不可把暫時預估誤寫成已入帳。

### LINE 通知

- Worker 使用 LINE Messaging API Push；通知會計入官方帳號訊息額度，且按實際收件人數計算。
- 會員回報匯款（`payment_reported`）只通知管理員。
- 管理員確認訂金、可取貨、完成訂單等狀態更新，依事件通知會員與管理員。
- 低庫存、生日券與管理員測試通知為其他通知事件。
- 不要在 UI 改版時改寫通知觸發條件、收件人邏輯或訊息文字；若需要調整，另列為後端工作。

### 退換貨與公開文案

付款完成視同同意代購資訊與交易規則。首頁需保留店家提供的原意，包括：

- 預購需經海外出貨、海運與集運，實際到貨時間受地區、批次、海關與天候影響。
- 不保商品價格漲跌；付訂後價格波動不影響已成立訂單。
- 到貨通知後需於 7 日內付尾款；延後需主動告知，逾期可能視同棄單，訂金不退還且商品不保留。
- 預購商品訂金為總價 50%。
- 潮玩為大量生產產品，不保官方產品瑕疵、國際物流盒損、海關查驗拆檢、寄送遺失／毀損。
- 店主目前要求「不接受任何原因退換貨」的公開說明；不可自行加入七天鑑賞期、退款保證或其他法律承諾。若文案與法規顯有衝突，先標記風險交由店主確認。

## 5. UI/UX 設計要求

### 視覺方向

- 方向關鍵字：收藏店的策展感、玩具拆盒前的期待、精準的資訊層級、成熟留白、黑白基底與鵝黃焦點。
- 可以有大膽構圖、編輯感、非對稱、精緻微互動，但不能以炫技取代商品、價格、庫存與付款資訊。
- 避免：泛用 SaaS 卡片牆、過量圓角膠囊、無意義漸層、玻璃擬態、大量 emoji、廉價促銷紅色、過度陰影、文字太小、按鈕像裝飾。
- 商品圖片要有呼吸感與一致的裁切／留白，不要因 `object-fit: cover` 把盒裝商品切掉；圖片載入失敗需有可理解的 fallback。
- 中文字體、數字金額與英文小標要有清楚層級；表單輸入字體在手機不可小於 16px，以避免瀏覽器自動放大。

### 響應式斷點與操作

- 先以 390px 寬手機設計，再驗證 768px 平板與 1440px 桌機。
- 首頁商品格：手機 2 欄、平板 4 欄、桌機 4 欄。
- 手機 Header、商品卡、取貨選項與結帳欄位不可產生不必要的兩行截斷；長訂單編號、商品名稱、狀態 chip 要能自然換行或折疊。
- Dialog 內容可滾動時，關閉按鈕固定或 sticky 在右上角；不要要求使用者滑到頁面最上方才能關閉。
- 點擊目標至少適合觸控操作；焦點樣式、鍵盤操作、`aria-label`、表單錯誤關聯不可刪除。
- Success、error、loading、empty、disabled、expired、permission denied、network failure 都要有設計，不可只設計 happy path。

### 轉化與信任

- Hero 只保留一個主行動（開始挑選／先看現貨），規則與客服是次要行動。
- 商品卡優先呈現：商品名、規格入口、現貨／預購、可售量、價格、加入購物車。
- 預購的 50% 訂金、現貨付款差異、到貨後運費通知必須在決策點附近出現，而不是藏在最後一段小字。
- 結帳流程要顯示目前步驟、即將發生的事、會不會保留庫存、何時需要付款或等待客服。
- 賣貨便與宅配的費用責任要用短句清楚說明：賣貨便由 7-11 收取；宅配實際費用到貨後由客服通知；本站結帳不預先加總未知運費。
- 管理後台優先呈現「現在需要處理什麼」：待確認款項、賣貨便待核對、可取貨、低庫存、逾期／退款。
