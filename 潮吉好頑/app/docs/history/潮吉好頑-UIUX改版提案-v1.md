## 1. 現況問題（P0 / P1 / P2）

### P0（影響下單完成率、信任感或資料正確性，建議優先處理）

1. **Hero 大面積純鵝黃底，違反「黃色只在一處」的品牌節制原則。**
   `.hero{background:var(--yellow)}` 讓整個 Hero 區塊（含左右兩欄）都是黃底，黃色不再是「焦點」而是「背景」。同時 `.hero-art`（舊版圓形旋轉印章卡＋陰影）還留在 CSS 裡是死碼，代表視覺語言在交接過程中沒有徹底收斂，目前 `index.html` 用的是 `.hero-selection` / `.hero-product-spotlight` 這組新結構，但底色仍沿用舊的滿版黃。
2. **Eyebrow label 與「01 / 02」編號標籤仍大量存在，且並非真正的步驟序列。**
   `PRODUCT DETAIL`、`CHECKOUT`、`MEMBER PROFILE`、`ADMIN`、`PAYMENT`、`MY ORDERS`、`LINE FRIEND` 等每個 dialog 開頭都有一段 tracked-out 全大寫英文 eyebrow；首頁商品區與購物須知區也各自掛著 `01 SELECTION SHELF` / `02 BEFORE YOU CHECK OUT`。這是最典型的「AI 生成感」樣板痕跡：標籤本身不承載資訊，只是裝飾性前綴，而且只有兩個區塊，稱不上序列。
3. **購物車商品名稱旁用中點分隔多個中繼資訊，可讀性差。**
   `app.js` 第 126 行：`${money(item.price)} · ${item.category}`，以及優惠券卡片、訂單卡片多處都用「A · B · C」串接。在手機窄版面容易造成資訊擠成一行、語意不清。
4. **商品卡圖片裁切策略前後矛盾（曾修但未收斂）。**
   `.product-image img{object-fit:cover}` 在 CSS 前段設定，後段又被「Responsive image fit」區塊 override 成 `object-fit:contain`。兩條規則同時存在、互相覆蓋，之後任何人調整順序都可能讓盒裝商品被裁切邊角，且不易一眼看出目前實際生效的是哪條。這類「疊加式修補」在 499 行的 CSS 檔尾端還出現三次類似「補丁註解」（`/* Homepage readability refinements. */`、`/* Responsive image fit */`、`/* With the three-step rail removed... */`），代表系統已經靠不斷疊加覆寫規則維持，而不是重構成單一事實來源，長期會愈改愈難預期效果。
5. **表單驗證訊息用 `role="alert"` 但視覺上與一般說明文字（`.dialog-copy`）幾乎同色系，只差背景色塊。**
   對比 `PRODUCT.md` 「重要訂單、付款與庫存結果不得只以顏色表示，需同時提供文字說明」的原則，目前 `.form-error` 已有文字，符合基本要求；但錯誤與成功都只用淡色底（`#fff0ed` / `#edf8ee`）加文字色，在手機小螢幕、陽光下對比可能不足，且沒有圖示輔助辨識，純靠讀字。
6. **付款方式與取貨方式的關聯規則只藏在 JS 邏輯裡，UI 沒有即時說明。**
   目前已統一為本站到店取貨與宅配僅接受匯款／轉帳；賣貨便則是外部付款流程。付款方式限制已在前端、Worker 與 Supabase RPC 同步執行，避免使用者選錯或繞過前端送出。
7. **管理後台「訂單管理」單一長列表，缺乏待辦優先序視覺化。**
   目前後台訂單卡片全部混在同一個 `admin-order-list` 裡，靠上方一個下拉篩選狀態；沒有像 `PRODUCT.md` 要求的「儀表板：待確認款項、可取貨、低庫存、預購待到貨提醒」那樣把「現在最需要處理什麼」直接攤在最上層，管理員仍需主動篩選才看得到待辦，效率低於需求規格的期待。

### P1（明顯拉低質感／體驗一致性，但不阻斷下單或管理）

8. **按鈕系統只有二階層（primary 黑底白字／secondary 白底黑邊），沒有第三階層區分「高風險操作」（例如取消訂單、退款）與一般次要操作。** 目前 `.remove`、`.text-button` 都用底線＋文字色處理，取消訂單／退款這類會影響金流與庫存的操作，視覺上和「稍後再回報」這種輕量操作幾乎沒有區別。
9. **卡片圓角、邊框寬度、陰影深淺在商品卡、後台卡、對話框、選物托盤（pill 型）之間不統一**，沒有一套明確的「圓角語言」（例如：容器 8–10px、藥丸 999px、圖片 6–8px），是逐頁各自定的數值（10px、12px、8px、7px、6px 混用），使用者滑動頁面時圓角感覺會「跳」。
10. **`.filter`、`.admin-chip`、`.status-chip` 三套「標籤／篩選」樣式並存，視覺語言不同（一個是滿版藥丸按鈕，一個是細邊框小 chip，一個是淡底圓角矩形）**，其實語意接近（分類、狀態、篩選），值得統一成一套 chip 系統並用顏色角色（中性／進行中／完成／警示）區分，而不是各自命名各自的配色。
11. **Hero 的「加入選物盒」按鈕文案與購物車實際名稱「購物車」不一致**（`hero-add-button` 文案是「加入選物盒」，但 header 與 drawer 都叫「購物車」），依 frontend-design 的原則「同一動作在整個流程中要維持同一詞彙」，這種命名飄移會讓使用者一瞬間分不清楚是不是同一個東西。
12. **賣貨便待確認訂單流程在購物車／首頁完全沒有視覺標記**，一旦使用者選了賣貨便並跳轉出去，回到本站後除非主動打開「我的訂單」，否則不會被提醒「這筆還在待確認」，容易造成使用者誤以為訂單已完成或忘記後續動作。
13. **管理端「商品與規格」頁把「新增商品」「新增規格」都設為 `<details open>` 常態展開**，在商品數量變多後，這兩個大表單會把整個管理頁面往下推很長一段，增加了找「既有商品清單」所需的捲動量。

### P2（打磨、細節與長期一致性）

14. `.hero-selection-mark{content:"PLAY REPEAT"}` 這類純裝飾性英文標語，對中文為主的頁面幫助有限，可考慮拿掉或改成真正提供資訊的內容（例如即時庫存提示）。
15. 訂單狀態英文 key（`pending_payment`、`ready_for_pickup`…）直接當成 CSS class 名稱使用（`.status-pending_review`），可運作但擴充新狀態時容易漏改對應樣式，建議之後改用資料驅動的狀態顏色 mapping，而非逐一寫 class。
16. 管理後台「商品與規格」卡片已經用了 `--product-accent` 依序輪替四色做視覺分組（不錯的巧思），但前台商品卡沒有對應概念，前後台視覺語言不同調。
17. 目前 CSS 檔案沒有分區塊（section comment）以外的命名系統（無 BEM／無 utility class 系統），499 行全部平鋪，長期擴充容易互相覆寫（如同 P0-4 的例子）。

## 2. 新首頁 Wireframe

### 設計方向（提案，等你確認）

延續既有「鵝黃＋黑＋白」與「收藏店策展感」，但把黃色收斂成**單一焦點**（目前的滿版黃底 Hero 建議改為：白／米色背景 + 一個黃色重點物件，例如陀螺形的圖形裝置或价格牌），拿掉英文 eyebrow 與「01/02」編號，改用真正描述內容的中文小標；購物須知不做成純文字清單，而是做成「三個決策點卡片」（現貨規則／預購訂金／退換貨），對應 `CODEX_UI_UX_HANDOFF.md` 要求的「預購 50%、現貨付款差異、到貨後運費通知要出現在決策點附近」。

### 桌機版（1440px）— 重點差異

- Hero 改為左右不對稱兩欄（比例約 55/45），左側文字＋主行動，右側商品聚焦卡；**右側卡片背景用白／米色卡片＋黃色僅作邊框或一個角標**，不整片黃。
- 商品區改為 4 欄格線（維持規格書「桌機 4 欄」要求），搜尋列與篩選 chip 同排，不需像手機版換行堆疊。
- 購物須知三張決策卡改為橫向並排（3 欄），維持「決策點」的可掃描性而不是變成長段落。
- 店取／客服資訊列在桌機可以與 Hero 底部並排、或作為一條較低調的次要色帶，避免和 Hero 搶視覺權重。

## 3. 核心流程 Wireframe（商品詳情 → 購物車 → LINE 好友檢查 → 結帳 → 付款 → 會員中心）

以下用文字流程圖表示每一步的畫面內容與狀態分支，狀態命名沿用規格書既有的九種訂單狀態，不新增或更改。

```
[商品卡] --點擊「查看規格」--> [商品詳情 Dialog]
   狀態：載入中 / 正常 / 無圖片(fallback icon) / 已售完 / 已達限購

[商品詳情 Dialog]
  規格選擇 → 顯示：現貨可售量 或 預購到貨說明（海運/集運/海關措辭）
  → 若為預購：在價格旁直接顯示「訂金 50%＝NT$xxx」，不要等到結帳才出現
  → [加入購物車]（賣貨便不在商品詳情直接跳轉）
  狀態：加入成功(toast) / 已達限購(disable+文字)

[購物車 Drawer]
  商品明細 → 選擇取貨方式（到店取貨 / 賣貨便 / 宅配）
  → 依選擇即時顯示對應費用規則文字（賣貨便由7-11收、宅配到貨後客服通知）
  → 若混合現貨+預購 → 顯示「現貨／預購將分開建立訂單」，並各自選擇取貨方式

  → 預購選賣貨便：[前往結帳]，本站先收匯款訂金；到貨後客服通知並開立賣貨便
  狀態：空購物車 / 一般 / 賣貨便不可用(inline提示) / 送出中(loading)

  ↓（若選本站結帳，且尚未通過 LINE 好友檢查）

[LINE 好友檢查 Dialog]
  說明：需要加入官方 LINE 才能收到訂單通知
  [加入潮吉好頑官方 LINE] → 外部連結（測試帳號 @345adwzw，不可替換為正式客服帳號）
  [我已加入，重新檢查] [先回首頁瀏覽]
  狀態：檢查中(loading spinner+disable按鈕) / 未通過(維持dialog+錯誤文字)
       / 通過(自動關閉→繼續結帳) / 網路失敗(可重試文字)

  1. 會員資料（姓名/手機，LINE登入帶入姓名可編輯）
  2. 取貨方式（到店取貨／賣貨便／宅配；宅配僅選宅配時顯示收件人／電話／地址必填）
  3. 付款方式（本站匯款／轉帳；現貨賣貨便外部付款，預購賣貨便先付本站訂金）
  4. 收款帳戶選擇 + 訂單試算（商品總額－優惠券－點數＝預估應付；不含賣貨便/宅配未知運費）
  [保留商品並取得匯款資訊]
  狀態：送出中(loading, disable按鈕防重複送出) / 驗證錯誤(逐欄位inline錯誤，
       非只在頂部一條訊息) / 成功(轉付款Dialog) / 逾時保留失敗(缺貨提示)

[付款 Dialog]
  訂單編號＋應付金額（訂金或全額，清楚標示是哪一種）
  收款帳戶資訊（可複製帳號）
  [輸入匯款末五碼並送出] 或 [稍後再回報]
  明確倒數提示：預購2小時／現貨24小時內需完成，逾期自動取消並釋放庫存
  狀態：待回報 / 已送出待確認(轉orders查看) / 已逾期(說明已被取消)

[我的訂單 Dialog]
  列表：狀態 chip + 摘要 + 對應動作（補回報末五碼／查看詳情）
  賣貨便待確認訂單需要有清楚視覺標記（P0-12 對應修正）
  狀態：載入中 / 無訂單(empty state引導去逛商品) / 一般列表

[會員中心（Profile）]
  首次登入：姓名/手機必填 + 生日/地址選填
  已登入：顯示點數餘額、折抵規則、近期異動、收件地址
  狀態：未填寫(引導填寫) / 已完成 / 儲存中 / 儲存失敗

## 4. 後台新版資訊架構

沿用需求規格書的七大模組，但把「營運概況」從單純統計數字，升級為**待辦導向的儀表板**，其餘模組維持既有分頁，只調整層級與掃描效率。

```
營運概況（首頁，登入後預設頁）
├─ 待辦區（可點擊直接跳轉到對應篩選好的訂單/庫存列表）
│   ├─ 待確認款項 N 筆 →（點擊跳訂單管理，預先套用篩選）
│   ├─ 賣貨便待確認 N 筆 →
│   ├─ 可取貨 N 筆 →
│   └─ 低庫存規格 N 項 →
└─ 次要統計：會員數、[重新整理][測試LINE通知]

訂單管理
├─ 頂部：狀態 chip 快速篩選（取代目前純文字下拉，chip 可多選）
├─ 搜尋：訂單編號/姓名/手機/末五碼
└─ 列表：卡片維持現有欄位，但「需要處理」的訂單（待確認款項、
   賣貨便待確認）排序置頂，而非單純依建立時間

會員與點數
├─ 點數規則設定（既有）
└─ 會員列表＋搜尋（既有，維持點數帳本明細）

收款帳戶
└─ 帳戶清單＋新增/編輯（既有結構已足夠，優化：停用帳戶視覺降低權重）

商品與規格
├─ 建議：把「新增商品」「新增規格」表單預設收合（P1-13），
│  列表區塊往上移，減少管理員每次都要往下捲動
└─ 既有商品清單（保留目前依色系分組的巧思，前台可呼應此語言）

庫存異動

## 5. 新設計系統（Design Tokens）

### 色彩

| Token | 值 | 用途 |
| --- | --- | --- |
| `--ink` | `#161616` | 主文字、主按鈕底色 |
| `--yellow` | `#f4cf57` | **唯一**焦點色：僅用於一個 Hero 重點物件、選中狀態邊框、極少數 CTA 角標 |
| `--cream` | `#fffdf7` | 頁面底色 |
| `--paper` | `#f6f1e3` | 卡片／區塊底色（次要於白色） |
| `--line` | `#d9d1bf` | 邊框、分隔線 |
| `--muted` | `#68645b` | 次要文字 |
| `--success` | `#23733d`（文字）／`#edf8ee`（底） | 成功狀態 |
| `--danger` | `#8a3025`（文字）／`#fff0ed`（底） | 錯誤、高風險操作 |
| `--warning` | `#745b08`（文字）／`#fff0b8`（底） | 待確認、低庫存 |

原則：**整個網站只保留一處「大面積黃」**（提案為 Hero 焦點商品卡的邊框或角標），其餘用黃色的地方一律限縮為小面積標記（選中態、警示 chip 邊框），不再有整片黃底 Hero 或整片黃底 CTA。

### 字體

- 中文與 UI 統一沿用 `Noto Sans TC` / `PingFang TC` / `Microsoft JhengHei` 堆疊（維持既有，符合品牌調性，不需引入新字體）。
- 字級層級（清理現有 clamp 值到一致比例）：
  - 展示大標：`clamp(2.4rem, 6vw, 4.2rem)`（現行 Hero 到 5.8rem 偏大且與其他標題差距過大，建議收斂）
  - 區塊標題：`clamp(1.8rem, 3.5vw, 2.6rem)`
  - 內文：`16px / 1.65`
  - 說明文字／meta：`13px`
  - 手機輸入框字體：一律 `≥16px`，避免 iOS Safari 自動縮放（現況已符合，維持）

### 間距

- 採 4px 基準的間距尺度：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96px`，取代目前散落的 `7px / 9px / 13px / 17px / 22px` 等非規律數值，讓卡片內距、表單欄位間距在不同模組間一致。

### 圓角

- 容器（卡片、對話框）：`10px`
- 輸入框、按鈕：`7px`
- 圖片：`8px`
- 藥丸型（chip、選物托盤）：`999px`
- 不再混用 `6/7/8/9/10/12px` 六種數值。

### 按鈕三階層

1. **Primary**：黑底白字，用於唯一主行動（加入購物車、送出訂單、儲存）。
2. **Secondary**：白底黑邊，用於次要但仍需要明確點擊的操作（取消編輯、重新整理）。
3. **危險／高風險**（新增）：白底＋`--danger` 邊框與文字，用於取消訂單、退款、刪除等操作，避免與一般次要按鈕混淆。

### 輸入框

- 統一 `border:1px solid var(--line); border-radius:7px; padding:10px 12px`，focus 時邊框改 `--ink` 並加 2px focus ring（目前部分表單缺乏可見 focus 樣式，需補齊以符合鍵盤操作要求）。
- 錯誤狀態：邊框改 `--danger`，並在欄位下方（非僅頂部彙總）顯示對應錯誤文字。

### 卡片

- 商品卡、後台卡、訂單卡統一 `border:1px solid var(--line); border-radius:10px; background:#fff`，陰影僅用於「浮動於內容之上」的元件（dialog、selection tray、toast），一般卡片不加陰影，靠邊框與留白區分層級。

### 狀態 Chip（統一 `.filter` / `.admin-chip` / `.status-chip` 三套為一套）

```
中性（分類/篩選）：border 1px var(--line), bg #fff, 選中時 bg var(--ink) 文字白
進行中/待確認：bg var(--warning-bg) 文字 var(--warning)
完成/可取貨：bg var(--success-bg) 文字 var(--success)
已取消/已退款：bg #eceae3 文字 var(--muted)
```

### Dialog

- 統一拿掉英文 eyebrow（`PRODUCT DETAIL` 等），改為中文標題直接開頭（例如「商品規格」而非「PRODUCT DETAIL / 商品規格」兩層）。
- 關閉按鈕固定右上角、內容捲動時維持可見（現況已符合，維持）。

### Toast

- 維持現有黑底白字、底部置中浮出的樣式，但區分「成功」（維持黑底）與「錯誤」（改用 `--danger` 背景），目前全部 toast 統一黑底、不分語意色，使用者需要讀完文字才知道是好消息還是壞消息，改為顏色+文字雙重提示（符合 PRODUCT.md 的可及性原則）。

## 7. 微互動與錯誤／載入／空狀態

### 微互動（僅保留「有回饋意義」的動效，避免逐卡片 hover 動畫的樣板感）

- 加入購物車：按鈕短暫轉為「已加入 ✓」再還原，取代目前純靠 toast 通知（toast 仍保留，但按鈕本身也給即時回饋）。
- 購物車角標數字變動時做一次輕微縮放（scale）強調，而非無提示地直接跳數字。
- 庫存保留倒數：若後續要顯示「保留中，剩餘時間」，用靜態文字＋每分鐘更新一次即可，不需要跑動畫倒數計時器（避免造成不必要的緊張感或效能負擔）。
- Dialog 開關：維持現有淡入即可，不需要額外滑動或彈跳效果。
- `prefers-reduced-motion`：維持現況已有的處理（`html{scroll-behavior:auto}` 等關閉平滑捲動與動畫），新增的微互動同樣要在此媒體查詢下關閉。

### 錯誤狀態

- 表單：欄位層級 inline 錯誤（現況多數是頂部單一錯誤訊息，建議補上欄位旁提示，例如手機格式錯誤要標在手機欄位旁，而不是籠統一句「請檢查表單」）。
- 網路失敗（LINE 好友檢查、結帳送出）：提供「重試」按鈕，而非只顯示「發生錯誤」。
- 庫存不足／已售完：商品卡與詳情頁直接 disable 加入購物車按鈕並顯示原因文字，而不是等送出訂單才報錯。

### 載入狀態

- 商品清單、訂單清單、後台各分頁：現況已有「載入中」文字，建議統一改為骨架屏（skeleton）淺灰色塊，減少文字跳動感，尤其商品格與後台訂單列表。

### 空狀態

- 我的訂單為空：引導文字＋「去逛商品」按鈕（現況只有極簡文字，建議補上行動呼籲）。
- 後台各列表為空：現況已有 `.empty-state` 樣式（維持），文案可再檢查是否都說明「為什麼是空的、下一步做什麼」。
