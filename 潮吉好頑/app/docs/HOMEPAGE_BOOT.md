# 首頁開機與預載

改首頁／商品頁／訂單頁的開機流程、內嵌資料、LIFF SDK 預載或前台 module 的靜態 import 時讀這份。從 `AGENTS.md` 移出。

首頁開機：Worker 回傳首頁時若 150ms 內取得型錄，會把型錄以 `<script type="application/json" id="cj-catalog-data">` 內嵌在 body 最後並移除 `<head>` 的 `catalog-prefetch.js` 提早請求（`src/share-meta.ts`；逾時則退回請求 `/api/catalog`）。執行設定（同 `/api/config`，只來自部署設定）在首頁、商品頁與獨立訂單頁（`src/orders-page.ts`）一律內嵌為 `cj-config-data`，前台以 `embedded-config.js` 的 `takeEmbeddedConfig` 先讀它，沒有才請求。從 LIFF 開啟首頁或商品頁時（網址有 `liff.*`／`cj_liff_oauth` 參數，或 UA 有 `LIFF`），Worker 在 `<meta charset>` 後插入 LINE SDK 的 preload（`share-meta.ts` 的 `liffSdkPreloadMarkup`，網址與 `public/liff-auth.js` 的 `LIFF_SDK_URL` 由測試比對），回應帶 `Vary: User-Agent`。`index.html` 與 `orders.html` 的 `<link rel="modulepreload">` 清單列出各自入口（`app.js`、`orders-page.js`，見 `scripts/build-modulepreload.mjs` 的 `PAGES`）整棵靜態 import 樹：新增、移除或改動前台 module 的靜態 import 後執行 `node scripts/build-modulepreload.mjs`（不在 build 自動執行，`tests/frontend/modulepreload.test.mjs` 會擋下過期清單）；後台以動態 import 延後載入的 module 不列入。開機計時報告（`?cj_timing=1`，`boot-timing.js`）首頁與訂單頁共用，歷次結果分開累計；恢復登入與 `GET /api/orders` 回應帶 `Server-Timing`（`src/server-timing.ts`，只有步驟名稱與毫秒數），報告顯示 Worker 內各步驟耗時。訂單頁恢復登入時帶 `include_orders: true`，Worker 在同一個回應附上訂單（`member-api.ts` 的 `ordersForRestoredSession`，與 `GET /api/orders` 共用查詢與限流；讀不到時不附帶、前台改請求 `GET /api/orders`，不影響回傳新的 access token）。
